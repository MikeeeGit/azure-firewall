# Contributing

Describe the problem, resulting behavior and verification in each change. Preserve policy priorities, ordered rule collections and state addresses unless the migration is explicit. Use synthetic resource IDs and example domains; never submit state, plans, credentials or organization-specific configuration.

Run the [credential-free checks](docs/testing.md). Public CI cannot validate real Azure behavior. Document separately any private integration checks and their scope. New cloud resources, advanced firewall features or changes to default traffic permissions need an explicit design discussion.
